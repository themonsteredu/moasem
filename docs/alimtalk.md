# 모아킷 알림톡 연결

보호자 리포트를 만든 뒤 MOAKIT 카카오톡 채널로 도착 안내와 링크를 보냅니다. 시험용 실제 메시지는 발송하지 않았으며, 연결 정보를 입력하고 승인 문구로 수신 시험을 하는 단계가 남아 있습니다.

## 화면에서 사용하는 방법

1. **보호자 리포트**에서 학생을 선택합니다.
2. 리포트를 작성하고 **리포트 만든 뒤 모아킷 알림톡 바로 보내기**를 선택하면 저장 후 발송을 요청합니다. 선택하지 않으면 리포트만 만듭니다.
3. **최근 리포트·알림톡**에서 기존 리포트를 열거나 알림톡을 보낼 수 있습니다. 최근 10개 리포트를 표시합니다.
4. **접수 완료 · 도착 확인 전**은 발송 요청이 접수된 상태입니다. 잠시 후 **도착 여부 확인**을 눌러 최종 결과를 확인합니다. ‘도착 확인’은 카카오 발송 결과이며 보호자가 리포트를 읽었다는 뜻은 아닙니다.
5. 실패가 확인된 건만 명시적으로 다시 보낼 수 있습니다. 1분 간격, 리포트당 총 3회까지입니다. 통신 중단 등으로 결과가 불명확하면 같은 리포트를 다시 보내지 않고 관리자가 Solapi 발송 내역을 확인해야 합니다.

알림톡이 실패해도 리포트는 남습니다. 보호자 링크는 로그인 없이 기존 만료일까지 사용할 수 있습니다. 만료된 리포트, 보호자가 바뀐 리포트, 잘못된 국내 휴대폰 번호에는 보내지 않습니다. 발송 내역 화면에는 전화번호 가운데 숫자를 가립니다.

## 먼저 연결할 항목

Solapi에서 사용할 카카오톡 채널이 **모아킷(MOAKIT)**인지 확인하고 아래 문구를 알림톡 템플릿으로 등록·승인받습니다. 이 작업에서는 채널 등록·템플릿 제출·계정 변경을 수행하지 않았습니다.

제안 문구:

```text
[모아킷]
모아셈 학습 리포트가 도착했습니다.
아래 링크에서 확인해 주세요.
#{리포트링크}
```

발송 시 바뀌는 값은 `#{리포트링크}` 하나이며 전체 HTTPS 주소를 넣습니다. 기존에 승인받은 문구를 사용한다면 변수 이름과 링크 형식이 같은지 먼저 확인합니다. 학생 이름·점수·오답 상세·강사 메모는 발송 요청에 포함하지 않습니다. 모국어 리포트 내용은 링크에서 봅니다.

Vercel 프로젝트의 서버 환경변수에 다음 값을 설정합니다. 비밀값은 채팅이나 저장소에 적지 않습니다.

| 항목 | 입력할 값 |
|---|---|
| `SOLAPI_API_KEY` | Solapi 연결 키 |
| `SOLAPI_API_SECRET` | Solapi 비밀 키 |
| `SOLAPI_PF_ID` | MOAKIT 채널의 프로필 ID |
| `SOLAPI_REPORT_TEMPLATE_ID` | 위 도착 안내 문구의 승인 템플릿 ID |
| `MOASEM_PUBLIC_URL` | 보호자가 접속할 공식 주소. 예: `https://moasem.vercel.app` |
| `MOASEM_ALIMTALK_ENABLED` | 연결 정보와 승인 문구 확인 후 `true`. 기본은 `false` |

모든 값은 서버 전용입니다. `NEXT_PUBLIC_` 이름으로 등록하지 않습니다. `MOASEM_PUBLIC_URL`에는 미리보기 주소나 로그인 보호 주소를 넣지 않습니다. SMS 대체 발송은 꺼 두었으므로 `SOLAPI_SENDER`는 현재 사용하지 않습니다.

## 배포 후 실제 수신 시험

운영자가 지정한 시험용 수신번호가 있는 학생으로 리포트를 만들고, 의도한 번호·채널인지 확인한 뒤 한 번 발송합니다. 카카오톡 도착, 리포트 링크 열기, 도착 여부 조회를 차례로 확인합니다. 번호나 채널을 임의로 골라 실제 메시지를 보내지 않습니다.

현재 로그인 PR #15와 영상 연결 PR #16 위에 쌓은 기능입니다. 선행 로그인 연결 문제의 실제 배포 후 확인이 필요합니다. 이 작업은 `work/report-alimtalk` 브랜치 자동 배포를 꺼 두었고, 배포·병합을 수행하지 않았습니다.

## 구현·검증 기록

- aiapp의 `moasem` 스키마에 `20260905111911_moasem_report_alimtalk.sql` 적용. 다른 앱 스키마는 수정하지 않았습니다.
- 보호자 리포트별 발송 시도를 저장합니다. 행 잠금과 고유 제약으로 여러 탭/서버의 중복 요청을 차단합니다. 발송 결과를 저장하지 못해도 먼저 남긴 시도 기록이 재발송을 막습니다.
- 서버가 현재 로그인 계정, 담당 프로그램, 등록된 보호자, 만료일을 확인합니다. 발송 대상과 링크는 서버에서 결정하며 브라우저가 준 번호·주소는 사용하지 않습니다.
- Solapi 요청은 한 번만 수행합니다. `showMessageList`, `strict`, 알림톡 타입과 `disableSms: true`를 명시하며 접수·실패·불확실·최종 도착을 구분합니다.
- 발송 결과 조회는 저장된 메시지 ID 한 건만 대상으로 합니다. 외부 응답 원문, 비밀키, 전체 전화번호를 화면에 반환하지 않습니다.
- `npm test` 63개 통과. 실제 DB 시험 `tests/alimtalk-database.sql` 통과, 시험 자료 모두 rollback. `npm run build` 성공, 기존 CSS 호환성 경고 1건 유지.
- 외부 발송은 모의 응답으로 검증했습니다. 실제 카카오톡 수신 및 기기별 브라우저 화면 검증은 아직 하지 않았습니다. 이전 점검의 로컬 브라우저 접속 차단과 배포 보류를 유지합니다.
- 보호자 리포트 자동 AI 작성, 채점 완료에 따른 무인 발송, 기관 미제출 주간 알림은 이번 구현 범위가 아닙니다.
