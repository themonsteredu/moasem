# 관리자·강사 로그인 확인 방법

배포된 새 버전에서 확인합니다. 현재 운영 주소에 새 로그인 화면이 없다면 아직 배포 전입니다.

## 첫 관리자 계정

1. `/login`으로 들어갑니다. 첫 실행에만 **관리자 계정 만들기**가 보입니다.
2. 관리자 이름, 기존 관리 키, 사용할 이메일과 비밀번호(10자 이상)를 입력합니다.
3. 등록 후 기관·학생 관리 화면으로 이동하며 명단을 자동으로 불러옵니다.
4. 로그아웃한 다음 이메일과 비밀번호로 다시 로그인합니다. 이제 관리 키를 입력하지 않습니다.

이미 이 이메일로 가입한 계정이 있으면 그 계정의 비밀번호로 확인합니다. 첫 관리자 등록이 끝나면 관리 키를 가지고 있어도 관리자 계정을 추가로 만들 수 없습니다.

## 강사 등록과 수업 배정

| 확인할 일 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| 신규 강사 | 강사 관리 → 이름·이메일·초기 비밀번호 입력 → 프로그램 선택 → 등록 | 목록에 강사와 담당 프로그램 표시 |
| 기존 강사 연결 | ‘기존 강사 연결’에서 등록된 이름 선택 | 기존 강사와 수업을 유지한 채 계정 연결 |
| 여러 수업 배정 | 한 강사에게 프로그램 두 개 선택 | 두 프로그램 모두 담당 목록에 표시 |
| 강사 로그인 | 별도 브라우저에서 강사 이메일·비밀번호로 로그인 | 내 학생, 대면 출석, 보호자 리포트 메뉴 표시 |
| 담당 범위 | 다른 강사에게만 배정한 프로그램도 준비 | 내 프로그램과 학생만 표시 |
| 실제 수업 운영 | 내 프로그램의 출석 저장, 내 학생 리포트 작성 | 저장 성공, 리포트 링크 생성 |
| 배정 변경 | 강사 관리 → 수정 → 프로그램 선택 변경 → 저장 | 다음 조회부터 변경된 명단 표시 |
| 사용 중지 | 강사 관리 → 수정 → ‘계정 사용 허용’ 해제 | 해당 강사 계정의 이후 로그인·조회·저장 차단 |
| 로그아웃 | 화면 상단 로그아웃 | 로그인 화면으로 이동, 새로고침해도 명단이 열리지 않음 |
| 보호자 보기 | 만들어진 리포트 링크를 다른 브라우저에서 열기 | 로그인 없이 리포트 표시 |

계정 안내 이메일은 자동 발송하지 않습니다. 관리자가 강사에게 이메일과 초기 비밀번호를 직접 전달합니다. 이미 가입한 이메일을 연결하면 기존 비밀번호를 그대로 사용합니다. 비밀번호 찾기·변경 화면은 이번 기능에 포함하지 않습니다.

## 개발 확인 기록

- `npm test`: 실제 화면·인증 처리·요청 처리 코드를 대상으로 36개 시험. 외부 인증과 브라우저 환경은 대역 사용.
- `npm run build`: 배포용 빌드 및 타입 검사.
- `tests/staff-database.sql`: 실제 moasem 저장소에서 기존 강사 연결, 여러 프로그램 배정, 배정 충돌의 전체 취소, 배정 해제, 계정 중지, 브라우저 직접 접근 제한 확인. 시험 자료는 트랜잭션 종료 시 모두 롤백.
- 실제 계정으로 로그인하는 브라우저 전체 흐름과 화면 크기별 확인은 새 배포가 준비된 후 위 순서로 진행해야 함.

## 운영 구조

- 인증은 Supabase Auth, 모아셈 권한은 `moasem.staff_accounts`에서 확인. 다른 앱의 테이블·역할·비밀번호·전체 세션은 변경하지 않음.
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `MOASEM_ADMIN_KEY`를 기존 환경변수로 사용. 브라우저에 서비스 키를 전달하지 않음. 별도 공개 인증 키 불필요.
- 기존 공용 키 인증은 첫 관리자 등록 이외의 API에서 제거. 이전 `moasem-admin-key` 브라우저 저장값은 정리함.
- 계정 사용 상태는 매 API 요청마다 검사. 강사는 programs.instructor_id 기준으로 명단·출석·리포트에 접근. 보호자/기관 토큰 조회는 기존 방식 유지.
- 액세스·갱신 토큰은 HttpOnly 쿠키. 운영 환경 Secure, SameSite=Lax. 액세스 만료 후 갱신하며 갱신 쿠키는 발급 시점부터 8시간. 로그아웃은 해당 세션만 해제.
- 첫 관리자 등록과 강사/프로그램 배정은 각각 DB 잠금으로 동시 요청을 직렬화. 저장 실패 시 다른 요청이 연결했을 수 있는 Auth 사용자를 삭제하지 않으며 재시도 때 기존 이메일로 연결.
- `20260905095504_moasem_staff_accounts.sql` 적용 완료. 버전은 연결된 Supabase 마이그레이션 기록에서 받은 값.
- 새 테이블은 RLS 활성화, anon/authenticated 접근 및 함수 실행 금지, service_role 전용. Advisor의 ‘RLS Enabled No Policy’ 정보 항목은 이 서버 전용 구조에서 의도된 상태이며 직접 권한도 확인함. [Supabase 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)
- 기존 `generate_join_code` 검색 경로 경고와 submissions 익명 정책 경고는 이번 변경 범위 밖에서 발견되어 유지.
