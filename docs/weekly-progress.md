# 주차별 진도표

관리자·강사 메뉴 **주차별 진도** (`/weekly-progress`)에서 프로그램을 선택한다. 학생은 세로, 주차는 가로이며 한 번에 학생 25명과 최대 4주를 표시한다. 이름·주차 머리글은 표 안에서 고정되고 모바일에서는 좌우로 이동한다. 학생 이름은 개인 학습기록으로, 칸은 해당 주의 상세 기록으로 연결된다.

## 집계 기준

| 항목 | 기준 |
| --- | --- |
| 주차 | 프로그램 시작일부터 7일씩, 마지막 주는 종료일까지. 한국 날짜 기준으로 이번 주를 표시한다. |
| 등록 주차 불일치 | 시작·종료일로 계산한 주차와 `week_count`가 다르면 안내한다. 날짜나 주차 수를 자동 변경하지 않는다. |
| 진도 | 해당 주 `lesson_date`의 기록 수와 가장 최근 교재·단원·쪽수. 같은 수업 날짜는 저장 시각과 ID로 순서를 정한다. 지난 주 기록을 이월하지 않는다. |
| 과제 제출 | `due_on`이 해당 주인 과제 중 제출·확인 완료 건수 / 전체 건수. 현재 상태이며 과거 시점의 상태를 복원한 값이 아니다. |
| 기한 지난 미제출 | 미제출이면서 마감일이 한국 기준 오늘보다 이전인 과제. 오늘 마감은 포함하지 않는다. |
| 대면·줌 출석 | 각각 출석·지각 건수 / 저장된 출석 기록 수. 인정결석도 분모에 포함한다. 예정 수업 대비 출석률이 아니다. |
| 기록 없음 | 해당 주에 저장된 기록이 없는 상태. 결석·미제출로 추정하지 않는다. |
| 상세 | 선택 학생·주차의 모든 진도, 마감 과제와 현재 상태, 대면·줌 출석과 메모. 입력은 기존 개인 페이지에서 한다. |

이 화면은 현재 프로그램의 사용 중인 학생을 대상으로 한다. 다른 프로그램으로 이동했거나 사용 중지된 학생은 제외한다. 프로그램 기간 밖의 기록과 기존 리포트·오답 결과는 개인 페이지에서 별도로 확인한다. 사진 자동채점·리포트 자동 생성·알림 발송 기능은 이 작업의 범위에 포함하지 않는다.

## 확인 방법

1. 관리자 또는 담당 강사로 로그인 → **주차별 진도** → 프로그램 선택.
2. 수업 기간이 이미 시작된 시험용 프로그램의 학생 개인 페이지에서 날짜·교재·단원·쪽수를 저장한다. 저장한 날짜가 속한 주에만 진도 기록이 표시되는지 확인한다.
3. 기존 과제 관리에서 그 주 마감 과제를 등록한 뒤 개인 과제에서 제출·확인 상태를 변경한다. 진도표를 새로고침하면 제출 건수가 바뀌어야 한다.
4. 수업·출석에서 대면과 줌 기록을 각각 저장한다. 진도표의 두 출석 칸과 상세 목록이 구분되는지 확인한다.
5. 학생×주차 칸을 눌러 기록 전체를 확인한다. 상세의 **개인 진도 기록하기**, **과제 확인·수정**으로 기존 입력 화면에 이동할 수 있다.
6. 주차·학생 페이지·프로그램을 바꿀 때 이전 상세가 닫히는지, 강사에게는 담당 프로그램만 보이는지 확인한다. 태블릿 가로 1280×800과 스마트폰 세로에서 표를 좌우로 이동하고 상세를 연다.

2026-09-06 읽기 전용 DB 확인: 현재 프로그램은 2026-09-30~2026-10-21(날짜 기준 4주), 등록 주차는 12주다. 사용 중인 학생 1명이며 이 기간의 진도·과제·출석 기록은 각 0건이다. 따라서 초기 표의 ‘기록 없음’과 기간 불일치 안내는 실제 자료에 맞는 표시다. 원본 자료는 변경하지 않았다.

## 구현과 검증

- `GET /api/admin/weekly-progress`: 현재 직원 인증, 담당 프로그램·현재 학생 확인 후 표시할 학생 25명과 최대 4주 기록을 집계한다.
- `GET /api/admin/weekly-progress/[studentId]`: 선택 학생·한 주의 상세를 요청할 때만 읽는다.
- 조회마다 현재 프로그램 강사·학생 소속·활성 상태를 inner join으로 확인하고 `moasem` 스키마만 사용한다. 응답은 private/no-store/noindex이며 보호자 연락처·저장 경로를 포함하지 않는다. 개요에는 강사 메모를 포함하지 않는다.
- 기록은 정확한 총건수와 ID 순 페이지 조회로 모두 읽는다. 1,000건 초과 또는 서버 페이지 한도가 더 작아도 조용히 잘리지 않는다.
- 날짜 경계·부분 주차·중복 날짜·누락 기록·권한·페이지 처리·현재 SDK 쿼리·늦은 화면 응답에 대한 시험을 포함한다. `npm test` 161개, TypeScript 검사와 `npm run build` 통과.
- 실제 DB의 읽기 집계는 확인했다. 실제 로그인 후 저장→진도표 전체 흐름과 기기별 시각 검수는 배포 후 별도 확인한다.
- 기존 테이블을 읽으므로 DB 마이그레이션과 추가 유료 서비스 설정은 필요 없다.
