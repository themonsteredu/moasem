# 오답 유형과 보충영상 자동 연결

강사가 보호자 리포트를 작성할 때 등록된 오답 유형을 고르면, 그 유형에 연결한 기본 영상이 리포트에 함께 들어갑니다. 자동채점 이전에도 직접 작성하는 리포트에서 사용할 수 있습니다.

## 이번에 추가한 내용

- 기존 보호자 리포트 작성 화면에 유형명·코드·단원 검색, 학년 필터, 여러 유형 선택을 추가했습니다.
- 연결한 영상을 미리 보여주며, 여러 유형에 같은 영상이 있어도 한 번만 표시합니다.
- 영상이 없는 유형은 유형만 담습니다. 비공개·사용 중지 영상은 자동 첨부하지 않습니다.
- 추가 학습 내용과 영상 주소를 직접 적는 기존 방식도 유지합니다.
- 보호자 화면은 오늘 결과 / 이번 주 과제 / 같이 볼 영상, 세 부분을 유지합니다. 등록된 베트남어·중국어 설명은 먼저 크게, 한국어 유형명은 아래 작게 표시합니다. 해당 언어 설명이 없으면 한국어 유형명만 표시하며 번역을 만들어내지 않습니다.
- 선택한 유형은 학생 학습기록과 연결해 누적 분석에 사용할 수 있게 저장합니다. 누적 분석 화면은 이번 범위에 포함하지 않습니다.
- 작성 당시의 유형명·설명·영상 제목·주소를 보관합니다. 이후 기준표 수정으로 이미 전달한 리포트 내용이 바뀌지 않습니다. 과거에 만든 영상 링크를 중지해야 할 때는 리포트 링크 만료도 함께 고려해야 합니다.

## 배포 후 확인 방법

1. 관리자로 로그인하고 **오답·영상**에서 유형 두 개에 같은 기본 영상을 연결합니다.
2. **보호자 리포트**에서 학생을 선택하고, 푼 문제 수 10 / 틀린 문제 수 2를 입력합니다.
3. 앞에서 연결한 유형 두 개를 선택합니다. 선택한 유형은 두 개, 함께 담을 영상은 한 개인지 확인합니다.
4. 이번 주 과제와 가정에서 함께할 일을 적고 **리포트 링크 만들기 → 열어보기**를 누릅니다.
5. 보호자 리포트에 유형 두 개와 영상 한 개가 나오는지 확인합니다. 영상 없는 유형, 추가 영상 주소, 베트남어·중국어 설명도 각각 확인할 수 있습니다.
6. 다른 학생으로 바꾸면 앞 학생의 선택과 생성한 링크가 사라지는지 확인합니다.
7. 강사 계정은 자기 담당 학생에게만 리포트를 만들 수 있어야 합니다. 기존 리포트 링크도 만료 전에는 계속 열려야 합니다.

## 저장 및 검증 기록

- 선행 작업: 로그인 기능 PR #15 (`feat/staff-login`). 이 변경은 해당 작업 위에 쌓은 별도 작업입니다. 로그인 기능의 배포 후 연결 확인이 먼저 필요합니다.
- 실제 적용한 저장 구조: aiapp의 `moasem` 스키마만 수정, `20260905103008_moasem_report_resources.sql`.
- 리포트 생성은 `create_staff_learning_report` 한 번으로 학습기록·유형 연결·보호자 리포트를 함께 저장합니다. 서버 전용 권한만 실행할 수 있고 현재 강사/프로그램 권한을 저장 시 다시 확인합니다.
- 자동 확인: `npm test` 47개 통과, `npm run build` 성공. 기존 스타일의 `align-items: start` 호환성 경고 1건은 남아 있습니다.
- 실제 DB 확인: `tests/report-resources-database.sql` 실행 성공. 여러 유형/중복 영상/영상 없는 유형/비공개·사용 중지 영상/추가 수동 영상/기준표 수정 후 기존 내용 유지/잘못된 유형/타 강사·사용 중지 계정/실패 시 부분 저장 방지를 확인했습니다. 시험용 자료는 모두 되돌렸습니다.
- 화면 구성과 학생 변경 동작은 React 시험으로 확인했습니다. 점검용 브라우저가 로컬 주소를 `ERR_BLOCKED_BY_CLIENT`로 차단해 실제 브라우저 조작과 노트북·1280×800 태블릿·휴대폰 화면 배치는 아직 확인하지 못했습니다.
- 로컬 화면 재현: `npm run build` → 별도 터미널에서 `npm start -- -p 3411` → `node tests/report-browser-server.cjs` → `http://localhost:3410/__screen`. 실제 화면 코드와 메모리 내 예시 응답을 사용하며, 이 화면 시험은 실제 로그인/DB 연결 검증을 대신하지 않습니다.
- Vercel 배포·main 병합은 하지 않았습니다. `vercel.json`의 `git.deploymentEnabled`에서 이 작업 브랜치만 자동 배포를 껐습니다. 다른 브랜치의 자동 배포 설정은 그대로입니다. [Vercel 공식 설정 설명](https://vercel.com/docs/project-configuration/git-configuration)
