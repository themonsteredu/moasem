# 학생 개인 학습기록

관리자 학생 명단 또는 강사 ‘내 학생’에서 이름을 누르면 `/students/[id]`를 연다.

- 위: 학생·학년·현재 프로그램과 기관, 가장 최근 수업의 교재·단원·쪽수·다음 과제.
- ‘수업 기록 추가’: 날짜, 교재, 단원, 쪽수, 배운 내용, 어려워한 부분, 내부 강사 메모, 다음 과제.
- 아래: 현재 프로그램의 진도 기록과 기존 학습 결과·보호자 리포트를 수업 날짜 역순으로 20개씩 조회.
- 원장은 전체 학생, 강사는 현재 담당 프로그램 학생만 조회/추가. 사용 중지 학생은 조회만 가능.
- 교재별 여러 진도를 동시에 표시하는 기능은 아직 없다. 상단은 가장 최근 기록의 교재 한 권이다.
- 진도 기록은 추가 방식. 정정은 새 기록에 남기며 같은 수업 날짜면 나중에 저장한 기록이 우선한다. 과거 날짜 입력은 최신 진도를 덮어쓰지 않는다.
- 기록 추가 시 알림톡이나 보호자 리포트를 자동 생성하지 않는다. 새 강사 메모는 이 직원용 화면에서만 조회한다.
- 응답이 끊기면 폼 내용을 잠그고 ‘저장 결과 확인’으로 동일 요청 번호를 다시 확인한다. 동일 요청 번호/내용은 한 행만 저장한다. 페이지를 떠나거나 새로고침한 뒤에는 먼저 지난 기록을 확인한다.
- 만료되거나 현재 보호자와 다른 리포트는 링크를 표시하지 않는다.

## 확인 방법 (배포 후)

1. 관리자 로그인 → 기관·학생 관리 → 학생 탭 → 학생 이름.
2. 수업 기록 추가 → 교재 ‘수학 3-2’, 단원 ‘곱셈’, 쪽수 ‘20~23’, 다음 과제 ‘24쪽’ → 저장.
3. 상단 진도와 아래 기록 확인 → 명단으로 돌아갔다가 다시 열어 저장 유지 확인.
4. 이전 날짜의 기록을 추가해 상단 최신 진도가 유지되는지 확인.
5. 기존 리포트가 있는 학생은 날짜별 학습 결과와 보호자 리포트 링크 확인.
6. 강사 계정으로 담당 학생은 열리고, 다른 프로그램 학생 주소는 차단되는지 확인.
7. 노트북·태블릿 가로(1280×800)·스마트폰 세로에서 입력/줄바꿈/화면 폭 검수.

## 구현과 검증

- DB: aiapp / moasem만 변경. `20260905220744_moasem_student_progress.sql` 적용 완료.
- `student_progress_entries`는 RLS 활성화, public/anon/authenticated 직접 접근 불가, service_role에 SELECT/INSERT만 허용.
- 읽기/쓰기 RPC는 매번 현재 직원 역할과 프로그램 배정을 확인한다. 직원·학생·프로그램 잠금으로 권한 확인과 조회/저장 사이 변경을 방지한다.
- 웹 API는 검증된 로그인 직원 ID만 전달하고 같은 출처 요청, 날짜·입력 길이·학생 ID를 검증한다.
- `npm test`: 100개 통과. `npm run build`: 성공. 기존 CSS align-items 경고 1개 유지.
- `tests/student-progress-database.sql`: 실제 DB에서 저장·동일 요청 재시도·다른 내용 충돌·날짜순·리포트·만료·페이지 나누기·담당 권한·비활성 학생·직접 접근 제한 확인, 전부 되돌림.
- 신규 객체 관련 security WARN/ERROR 없음. 기존 generate_join_code/submissions 권고는 이 기능에서 변경하지 않았다.
- 실제 브라우저/기기 시각 검수는 미완료. 이전 브라우저의 로컬 주소 접근 차단으로 우회하지 않았다.
- 배포 제한에 따라 work/student-progress 자동 배포 중지. 병합/배포/실제 발송은 하지 않았다.
