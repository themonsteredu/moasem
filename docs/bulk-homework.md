# 과제 일괄 등록

관리자와 담당 강사는 메뉴의 **과제 관리**(`/homework`)에서 프로그램 선택 후 **과제 일괄 등록**을 사용합니다. 위쪽 제출 현황의 사용법은 `homework-review.md`에 있습니다.

1. 프로그램을 선택합니다. 현재 사용 중인 소속 학생만 표시됩니다.
2. 전체 선택 또는 학생별 선택을 합니다. 한 번에 최대 200명입니다.
3. 과제명, 시작일, 마감일, 교재·쪽수·안내를 입력하고 **N명에게 과제 등록**을 누릅니다.
4. 성공 인원과 최근 등록 내역을 확인합니다. 아래 학생 이름을 누르면 개인 페이지에서 동일한 과제를 확인할 수 있습니다. 기존 학생 입장 링크의 숙제 목록에도 표시됩니다.

통신 오류가 나면 화면을 유지하고 **저장 결과 확인**을 누릅니다. 동일 요청은 한 번만 저장되며, 입력한 내용과 학생 선택은 결과를 확인할 때까지 잠깁니다. 완료 후 같은 내용을 새 요청으로 다시 등록하면 별도 과제로 저장되므로 최근 내역을 확인하세요.

저장 시점에 학생 소속이나 사용 상태가 바뀌면 전원 저장을 취소하고 명단 새로고침을 안내합니다. 일부 학생에게만 저장되는 방식이 아닙니다. 요청이 완료된 뒤 소속이 바뀌어도 같은 요청의 결과는 확인할 수 있고 새 프로그램에 과제를 추가하지 않습니다.

## 검증

- `npm test`: 선택한 학생만 전송, 프로그램 변경 시 늦은 이전 응답 무시, 연속 클릭 방지, 통신 오류 재시도, 날짜·중복·인원 검증.
- `tests/bulk-homework-database.sql`: 실제 DB에서 전원 저장, 완료 상태 보존 재시도, 다른 강사 차단, 소속·중지·없는 학생 혼입 시 전부 취소, 중복 학생 차단, 비공개 권한을 확인합니다. 시험 자료는 트랜잭션 종료 시 롤백합니다.
- 사진 경로 점검: 비공개 버킷 설정과 API 테스트로 업로드 → 제출 기록 연결, 만료 차단, 확실한 연결 실패의 파일 정리, 강사 확인 후 같은 사진 재시도의 중복 방지를 검증했습니다. 실제 휴대폰 촬영·실제 Storage 업로드를 끝까지 수행한 검증은 아직 아닙니다.
- 등록 화면에서 알림톡 발송이나 자동채점은 실행하지 않습니다.

## 적용 기록

Supabase provider migration `20260906020500_moasem_bulk_homework`를 aiapp의 moasem 스키마에 적용했습니다. 원본 SQL은 동일 이름으로 저장했습니다. 기존 배포 한도로 화면의 운영 배포 여부는 해당 PR 검사 상태를 확인해야 합니다.
