# 미제출·강사 확인 대기 모아보기

관리자와 담당 강사가 **과제 관리**(`/homework`)에서 프로그램을 선택하면 새 과제 등록 위에 표시됩니다. 기존 과제 기록을 읽으며 새 DB 표나 추가 유료 서비스를 사용하지 않습니다.

| 구분 | 기준 |
| --- | --- |
| 확인 대기 | 제출로 기록됐지만 강사가 아직 확인하지 않은 과제. 먼저 제출한 순 |
| 미제출 | 아직 제출로 기록되지 않은 모든 과제. 마감 전·시작 전 포함 |
| 기한 초과 | 미제출 중 마감일이 한국시간 오늘보다 이전인 과제. 오늘 마감은 제외 |
| 확인 완료 | 강사가 확인했다고 표시한 과제. 자동채점 성공이라는 뜻은 아님 |
| 전체 | 위 제출 상태 전체. 기한 초과는 미제출의 일부이므로 중복 합산하지 않음 |

숫자는 학생 수가 아니라 **학생별 과제 건수**입니다. 현재 선택한 프로그램에 소속돼 있고 사용 중인 학생만 집계합니다. 이동·사용 중지 학생의 과거 과제는 포함하지 않습니다. 마감일 또는 제출·확인 시각 뒤에 고유 번호로 정렬해 페이지 경계를 안정화하며, 한 페이지에 30건씩 표시합니다. 저장 중인 다른 화면이 있다면 건수와 목록 조회 사이에 상태가 달라질 수 있으므로 **현황 새로고침**으로 갱신합니다.

## 확인 방법

1. 로그인 → **과제 관리** → 프로그램을 선택합니다. 처음에는 **확인 대기**를 보여줍니다.
2. 아래 일괄 등록에서 시험용 학생에게 과제를 냅니다. **미제출**에 새 과제가 나타나는지 봅니다.
3. 해당 학생의 입장 링크에서 사진을 올리거나 개인 학습기록에서 제출로 표시합니다. 과제 관리로 돌아와 **현황 새로고침 → 확인 대기**를 누릅니다.
4. **사진 N장 보기**로 사진을 확인합니다. 사진이 없으면 버튼이 비활성화됩니다. 직접 받은 과제는 사진 없이 제출 상태만 기록했을 수 있습니다.
5. **학생 기록·상태 변경**을 눌러 기존 개인 과제 화면에서 강사 확인으로 변경합니다. 돌아와 새로고침하면 **확인 완료**에서 볼 수 있습니다. 개인 화면은 기존과 같이 최근 마감일 순 100건을 보여주므로 그보다 오래된 과제의 상태 변경은 이번 모아보기 범위에 포함하지 않습니다.
6. 프로그램·상태·페이지를 바꿀 때 앞서 보던 사진이 사라지는지 확인합니다. 사진 링크가 만료되면 **사진 새로고침**을 누릅니다.

## 보호 및 검증

- 목록과 개별 사진 요청마다 현재 관리자·강사 계정 및 담당 프로그램을 확인합니다. 서비스용 키는 서버에만 남습니다.
- 학생 소속·사용 상태, 프로그램 담당자를 조회 자체에서도 제한합니다. 다른 과제 번호를 입력해도 해당 프로그램의 현재 학생이 아니면 사진 링크가 발급되지 않습니다.
- 사진은 기존 비공개 `moasem-homework` 저장소를 사용하고, 선택한 과제의 사진에만 5분 링크를 발급합니다. 원본 저장 경로 필드를 목록·상세 응답에 별도로 반환하지 않습니다. 서명 링크 자체는 열람 권한이 있으므로 다른 사람에게 전달하지 않습니다.
- 응답은 비공개·캐시 금지이며 사진에는 공유 이미지 최적화를 사용하지 않습니다. 프로그램·필터·페이지 변경, 닫기, 오류 뒤에 늦게 도착한 응답으로 앞선 사진을 다시 표시하지 않습니다.
- API·화면 시험: 상태별 필터/정확한 건수, 한국시간 경계, 30건 페이지, 다른 강사·이동/중지 학생 차단, 오류와 빈 목록 구별, 사진 지연/새로고침, 기존 일괄 등록의 재시도 보호를 검사합니다. 설치된 Supabase 라이브러리로 실제 요청 형식도 별도로 검사합니다.
- 실제 DB에서 학생·프로그램 연결을 사용하는 집계 조회와 비공개 권한을 확인했습니다. 확인 당시 과제·사진은 0건으로, 실제 계정에서 휴대폰 촬영 → 업로드 → 이 화면 열람까지의 운영 시험은 별도로 필요합니다.
- 알림톡 발송, 자동채점, 상태 자동 변경은 수행하지 않습니다.
