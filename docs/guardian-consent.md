# 보호자 동의: 운영 화면과 영어 지원

2026-09-05. 화면 구성 승인 후 **관리자 동의서·학생별 동의 관리·보호자 동의 화면을 구현**했습니다. 영어를 추가해 한국어·영어·베트남어·중국어 간체를 지원합니다. 배포는 보류했으므로 현재 운영 주소에는 아직 반영되지 않았습니다. 실제 문구를 등록하고 배포 후 휴대전화 시험을 마친 다음 보호자에게 전달합니다.

## 승인 후 구현한 화면

색감·에스코어드림·로고와 파비콘 유지. 스마트폰 세로와 태블릿 가로 우선.

| 화면 | 구성 | 주요 동작 |
|---|---|---|
| 관리자 동의서 관리 `/consents` | 위에 문구 이름·작성일, 한국어/영어/베트남어/중국어 탭, 제목과 본문 입력, 아래 큰 저장 버튼 | 한국어는 기본으로 등록. 외국어 문구는 원장님이 제공한 내용만 사용. 수정본을 저장해도 이전 문구와 동의 기록은 보존 |
| 기존 학생 명단 | 학생 옆에 동의 대기/동의 접수 표시. 선택하면 보호자 언어, 동의 일시, 문구 이름, 링크 만료일 표시 | 링크 만들기·복사·사용 중지. 강사는 담당 학생만. 새 링크 발급 시 이전 링크 사용 중지 |
| 보호자 동의 `/consent/[token]` | 기관명·학생 이름, 모국어 동의 문구를 큰 글씨로, 아래 한국어 문구, 보호자 이름, 두 확인 항목, 큰 동의 버튼 | 로그인 없이 접속. 법정대리인임을 확인하고 문구에 동의해야 저장. 완료 시 한국 시간 기준 접수 시각 표시 |

학생 등록에 **만 14세 미만 여부(예/아니오/확인 필요)** 항목을 추가했습니다. 기존 학생은 자동 추정 없이 확인 필요로 표시합니다. 관리자만 연령 확인과 보호자 안내 언어를 수정할 수 있습니다. 만 14세 미만은 접수된 동의가 없으면 동의 대기, 현재 보호자·프로그램에 연결되는 접수 기록이 있으면 동의 접수로 표시합니다. 학생 정보 저장을 동의 완료로 표현하지 않습니다. 출석·리포트 등 다른 기능의 이용을 차단하는 정책은 이번 작업에 포함하지 않았습니다.

법정대리인 확인 항목은 링크를 가진 보호자의 자기 확인입니다. 휴대전화 본인 인증이나 가족관계 증명을 수행했다는 의미로 표시하지 않습니다. 실제 법률 문구는 자동 작성하거나 임의로 넣지 않았습니다.

## 구현된 처리

- 관리자가 문구 묶음을 새 버전으로 저장. 한국어는 필수이고 영어·베트남어·중국어 간체를 함께 넣을 수 있음. 게시한 문구를 덮어쓰는 경로 없음.
- 현재 담당 권한과 학생의 보호자를 확인한 뒤 보호자 언어로 링크 발급. 해당 언어 문구가 없으면 발급 차단. 한국어로 임의 대체하지 않음.
- 32바이트 난수 링크, 7일 만료. 저장소에는 원문 토큰 대신 SHA-256만 보관. 링크는 생성 응답에서만 반환하고 내역에는 노출하지 않음. 복사하지 못했다면 새로 발급.
- 새 링크 발급·명시적 사용 중지·학생의 보호자/프로그램 변경·보호자 연락처 변경·학생 비활성 시 이전 링크 차단.
- 실제 표시한 모국어와 한국어 문구, 학생·기관·프로그램 이름을 발급 당시 내용으로 보존.
- 이름·동의 확인·법정대리인 자기 확인을 모두 받고, 서버 시각·언어를 한 번만 기록. 같은 내용 재요청은 원래 접수 시각 반환. 다른 이름으로 덮어쓰기 차단.
- 링크를 사용 중지하거나 다시 발급해도 이미 받은 동의 기록은 보존. **링크 사용 중지는 동의 철회가 아님.** 동의 철회와 보관 기간에 따른 처리 정책은 별도 범위.
- 로그인과 현재 담당 프로그램 권한으로 관리자·강사 요청 보호. 보호자 응답에는 연락처, 관리용 학생 식별자, 다른 학생 목록을 반환하지 않음.
- 알림톡 전송은 호출하지 않음. 기존 모아킷 알림톡은 리포트 도착용 문구이므로 동의 링크에 재사용하지 않음.

## 저장 구조

aiapp 프로젝트의 `moasem` 스키마만 추가했습니다.

| 저장 항목 | 테이블 | 보존하는 내용 |
|---|---|---|
| 언어별 문구 버전 | `consent_documents` | 문구 이름, 언어별 제목·본문, 작성 관리자·시각 |
| 개별 동의 요청 | `guardian_consent_requests` | 학생·보호자·프로그램 연결, 토큰 해시, 문구 사본, 만료·사용 중지 시각 |
| 동의 접수 증거 | `guardian_consent_records` | 요청 연결, 이름·언어·동의 시각, 법정대리인 자기 확인 방식 |

기존 DB에 `consents`라는 빈 저장 자리가 별도로 존재합니다(확인 시 0건). 저장소에는 이를 사용하는 화면/API가 없었습니다. 기존 테이블을 변경하거나 가상 동의 기록을 이관하지 않았습니다. 이번 온라인 동의의 기준은 위 요청·문구·접수 기록입니다. 추후 종이 동의 기록과 통합한다면 출처를 구분하고 자기 확인을 본인 인증으로 오인하지 않도록 별도 설계해야 합니다.

모든 새 테이블은 RLS를 켜고 `anon`, `authenticated`, `PUBLIC` 접근을 차단했습니다. 서버 역할만 읽기·추가 가능하며 동의 요청의 `revoked_at`만 수정 가능합니다. 실제 받은 문구·서명 기록을 앱에서 수정·삭제할 권한이 없습니다. Supabase 검사에서 새 항목에 WARN/ERROR 없음. 서버 전용 설계에 따른 [RLS 정책 없음 INFO](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)와 아직 사용량이 없는 인덱스 INFO는 의도에 맞게 유지했습니다.

## 연결 계약

| 주소 | 호출 주체 | 기능 |
|---|---|---|
| `GET /api/admin/consent-documents` | 관리자·강사 | 최근 문구 버전 20개 조회 |
| `POST /api/admin/consent-documents` | 관리자 | `{label, translations: {ko: {title,body}, en?: {title,body}, vi?: {title,body}, "zh-CN"?: {title,body}}}` 저장 |
| `PATCH /api/admin/students` | 관리자 | `{student_id,is_under_14:true/false/null,guardian_language}`를 함께 저장 |
| `GET /api/admin/guardian-consents?student_id=...` | 관리자·담당 강사 | 최근 요청 20개와 접수 기록, 현재 링크 상태 조회 |
| `POST /api/admin/guardian-consents` | 관리자·담당 강사 | `{student_id,document_id}`로 새 요청. 응답 `path`는 같은 사이트에 연결할 상대 경로 |
| `DELETE /api/admin/guardian-consents` | 관리자·담당 강사 | `{student_id,request_id}`로 링크 사용 중지. 접수 기록 삭제 아님 |
| `GET /api/consent/[token]` | 보호자 링크 소지자 | 만료·관계 확인 후 문구·현재 접수 상태 조회 |
| `POST /api/consent/[token]` | 보호자 링크 소지자 | `{signer_name,language,document_id,accepted:true,is_legal_representative:true}` 접수 |

모든 변경 요청은 같은 사이트의 `Origin`을 확인합니다. 보호자 요청 시각·학생/보호자 식별자·인증 방식은 브라우저 입력을 신뢰하지 않습니다. 응답은 저장하지 않으며 검색 색인·리퍼러 전달 방지 헤더를 적용했습니다. 보호자 페이지에도 같은 리퍼러 정책과 검색 제외 설정을 적용했습니다. 문구는 일반 텍스트로 표시하며 HTML로 삽입하지 않습니다. 링크의 `?lang=en` 같은 언어 힌트는 만료/연결 오류 안내에만 사용하고, 실제 동의 문구와 접수 언어는 저장된 요청값으로 결정합니다.

## 검증과 다음 확인

- `npm test`: 92개 통과. 네 언어의 보호자 동의 흐름, 중복 클릭, 저장 결과 불명 시 조회로 복구, 관리자 문구 작성, 누락 번역 차단, 강사의 연령 수정 금지, 영어 리포트 저장 요청 검증 포함.
- `npm run build`: 성공. 관리자·보호자 동의 화면 포함. 기존 CSS `align-items:start` 경고 1개는 기존 코드의 경고입니다.
- `tests/guardian-consent-database.sql`: aiapp의 `moasem`에 실제 실행해 통과. 서비스 역할 권한으로 발급→열기→접수→중복 접수→다시 발급→사용 중지 검증. 다른 담당자·만료·보호자 변경·누락 번역 차단, 실제 동의 문구 보존 확인. 모든 시험 자료는 롤백했고 새 문구/요청/동의 기록 0건 확인.
- `tests/consent-english-database.sql`: 실제 DB에서 영어 문구→영어 동의→영어 리포트·오답 설명 저장 및 사본 보존, 연령 확인 권한과 수정 검증 통과. 모두 롤백. 새 문구·요청·접수 기록 0건 재확인.
- 화면 시험은 React에서 실제 구성 요소를 실행한 시험이며 실제 브라우저나 보호자의 휴대전화 확인을 수행한 것은 아님. 이 세션의 브라우저는 로컬 화면 연결이 차단된 상태여서 기기별 시각 검수는 배포 후 남아 있습니다.

배포 후 확인할 순서: 관리자 메뉴의 **보호자 동의서**에서 한국어+영어 시험 문구 등록 → **기관·학생 관리 → 학생**에서 만 14세 미만 여부와 안내 언어 영어로 저장 → 학생 옆 **동의 관리 → 동의 링크 만들기 → 링크 복사** → 스마트폰에서 로그인 없이 문구 확인·이름·두 항목 동의 → **동의 상태 새로고침**으로 접수 시각 확인. 영어 문구 미등록 시 링크 생성 불가, 새 링크 발급 후 이전 링크 사용 불가도 확인합니다.

## 영어가 적용된 범위와 추가 언어

영어 선택은 보호자 등록/수정, 동의 문구·보호자 동의 화면, 수동 리포트의 제목·안내 항목, 보충영상 언어와 오답 유형의 영어 설명 입력/CSV에 적용했습니다. AI가 리포트 본문을 영어로 만드는 기능은 후속 작업입니다. 기존 문구를 자동 번역해 채우지 않았습니다.

추가 후보는 필리핀어(타갈로그어)·러시아어·몽골어, 이후 우즈베크어·태국어·캄보디아어입니다. [다누리의 지원 언어](https://www.kihf.or.kr/web/lay1/bbs/S1T838C105/A/15/view.do?article_seq=1115897)를 참고한 운영 제안으로, 확정 우선순위는 참여 기관 보호자의 읽기 언어 수요로 정합니다. 국적만으로 선호 언어를 결정하지 않습니다. 영어 외 후보 언어는 아직 선택 목록에 추가하지 않았습니다.
